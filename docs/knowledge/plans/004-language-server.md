# Approach

Implements [SPEC-004](/specs/004-language-server.md). gopls cannot be linked
as a library, so `golpe lsp` is a **proxy**: editor ⇄ golpe lsp ⇄ gopls
(subprocess, stdio). For `.golpe` documents it regenerates Go on each
change (parser + generator are pure functions of the bytes) and sends gopls
`didOpen`/`didChange` for the virtual `x_golpe.go`; requests are rewritten
`x.golpe:pos` → `x_golpe.go:pos'` and responses back.

# Architecture

```text
lsp/jsonrpc.go   Content-Length framed JSON-RPC 2.0 over io.ReadWriter (stdlib only)
lsp/protocol.go  the handful of LSP structs we touch (Position, Range, Location, …)
lsp/sourcemap.go Map{ ToGo(golpePos) (goPos, ok); ToGolpe(goPos) (golpePos, ok) }
                 built by scanning /*line*/ and //line directives in generated code
lsp/proxy.go     routes methods; rewrites URIs/positions in params and results
lsp/server.go    document store, regeneration, diagnostics merge (golpe + gopls)
```

# Snippets

```go
// A segment maps a run of generated bytes that came from user source.
type segment struct {
	goStart, goEnd int // offsets in generated file
	golpeStart     int // offset in .golpe file (same length as the run)
}

type Map struct{ segs []segment } // sorted by goStart; binary search both ways
```

# Testing

- `sourcemap` round-trip property test over generator golden files.
- Proxy tests with a fake gopls (an in-process JSON-RPC peer that echoes
  positions), so CI does not need gopls.
- One integration test behind `-tags=gopls` that runs the real gopls.
