# Summary

`golpe` is the developer's entry point: `golpe generate` compiles
`.golpe` files to Go, and later `golpe fmt` and `golpe lsp`.

# Motivation

Developers need one command that fits Go's habits: run from anywhere in a
module, accept `./...` patterns, work from `//go:generate`, and fail CI when
someone forgot to regenerate.

# Requirements

- **R1** `golpe generate [patterns]` MUST generate every `.golpe` file
  matched; patterns are directories, files, or `dir/...`; default `./...`.
  `vendor/`, `testdata/` and directories starting with `.` or `_` are
  skipped, as `go` does.
- **R2** It MUST write a generated file only when its content changes (keeps
  mtimes stable for build caches and file watchers).
- **R3** Errors MUST be printed one per line as `path.golpe:line:col: msg`
  (paths relative to the working directory), and the exit code MUST be 1 if
  any file failed; other files are still generated.
- **R4** `golpe generate -check` MUST write nothing and exit 1, listing the
  stale files, when any generated file is missing or out of date.
- **R5** Generated files whose `.golpe` source was deleted SHOULD be removed
  (`-clean`, on by default) when they carry the generated header.
- **R6** `golpe version` and `golpe help` MUST work; unknown commands exit 2
  with usage on stderr. *(Done in the scaffold.)*
- **R7** Files SHOULD be generated in parallel; output order of diagnostics
  MUST be deterministic (sorted by path).

# Acceptance criteria

- [ ] `golpe generate ./...` in a fixture module produces the golden files.
- [ ] A syntax error in one file prints `a.golpe:3:5: …`, exits 1, and other
      files are still generated.
- [ ] `golpe generate -check` exits 0 right after generation, 1 after a
      `.golpe` edit.
- [ ] Running generate twice does not change mtimes.

# Out of scope

`golpe fmt` (a later spec), `golpe lsp` ([SPEC-004](/specs/004-language-server.md)),
watch mode.
